## 1. Project Overview

In public sector undertakings (PSUs), government procurement databases, and municipal enterprises, identical or functionally interchangeable materials are frequently catalogued under distinct codes, naming conventions, and unstructured descriptions.

For instance:
- **Enterprise A:** `MAT-101` | *Stainless Steel Bolt M10*
- **Enterprise B:** `BOLT-450` | *SS Hex Bolt, 10mm*
- **Enterprise C:** `77821` | *Hexagonal Stainless Steel Fastener M10*

Without an automated, intelligent cross-referencing system, enterprises suffer from:
- Redundant and duplicate safety stock across storehouses.
- Fragmented supplier negotiations and inability to aggregate purchasing power.
- Inconsistent material catalogues hindering inter-enterprise transfers.
- Inefficient procurement auditing and benchmark price comparisons.

This project designs, evaluates, and deploys a **hybrid Machine Learning Entity Resolution (ER) system** to discover functionally equivalent material records across public enterprises, group them into canonical clusters, recommend unified harmonised codes with verifiable technical evidence, and provide an interactive workspace for human procurement reviewers.

## 2. Official Project Objectives

The project strictly pursues three mandatory academic objectives:

1. **Objective 1 – Harmonised Grouping & Evidence Recommendation:**  
   Build a matching system that groups functionally equivalent material records and proposes one harmonised code with evidence.
2. **Objective 2 – Pairwise Entity Resolution Model:**  
   Produce an entity resolution model with pairwise precision/recall over a labelled sample.
3. **Objective 3 – Rigorous Evaluation & Human Reviewer Platform:**  
   Report pairwise precision/recall/F1, cluster purity. Baseline: exact string match. Deliver Reviewer UI showing proposed merges with evidence.

## 3. Technology Stack

| Layer | Tools / Libraries | Technical Role |
| :--- | :--- | :--- |
| **Language & Runtime** | Python 3.11+ | Primary execution environment |
| **Data Manipulation** | Pandas, NumPy | Data cleaning, schema alignment, record batching |

| **Clustering & Graphing** | NetworkX, Scikit-learn | Connected components / Agglomerative clustering for entity grouping |
| **Interactive Interface** | Streamlit, Plotly | Multi-page procurement dashboard and Reviewer Workspace |
| **Testing & Quality** | Pytest | Unit and integration testing across ML and parsing pipelines |
| **Version Control & Cloud** | Git, GitHub, Google Colab | Source tracking and GPU-accelerated experimentation |

## 6. Installation & Local Setup

### Step 1: Clone the Repository
```bash
git clone https://github.com/<your-username>/material-code-harmonisation.git
cd material-code-harmonisation
```

### Step 2: Configure Python Virtual Environment
We recommend Python 3.11 for guaranteed binary wheel availability across ML dependencies:
```bash
# Windows (PowerShell)
python -m venv venv
.\venv\Scripts\Activate.ps1

# Linux / macOS
python3 -m venv venv
source venv/bin/activate
```

### Step 3: Install Dependencies
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### Step 4: Environment Variables
Create your local environment file:
```bash
cp .env.example .env
```

### Step 5: Run Automated Tests
```bash
pytest tests/ -v
```

### Step 6: Launch Streamlit Reviewer Platform
```bash
streamlit run app/app.py
```

## 9. Academic Integrity & Ethics

This project adheres strictly to ethical data science practices:
- **No Synthetic Fabrication:** Metrics, precision, recall, and cluster purity are calculated strictly on evaluated test samples.
- **Data Provenance:** All catalogues are documented with licences and source attribution.
- **Human Oversight:** The system operates under a *human-in-the-loop* governance model, ensuring automated matching proposes merges while human procurement experts retain final approval authority.
